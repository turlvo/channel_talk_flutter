# 실제 Web SDK 검증: 2026-09-29

현재 작업 트리의 샘플 앱을 실제 Channel.io Web SDK와 연결해 확인했다.
사용자 제공 plugin key는 문서·소스에 저장하지 않았다. 새로운 익명 브라우저 세션을
사용했고 memberId, 프로필, 이메일·문자 수신 설정은 부팅에 전달하지 않았다.

## 환경과 검증 방법

- Flutter 3.19.6 / Dart 3.3.4, macOS, Chrome 154.
- `example/`에서 다음 명령으로 현재 소스를 실행했다.

  ```sh
  rtk proxy flutter run -d web-server --web-hostname 127.0.0.1 --web-port 8765 --no-pub
  ```

- 실제 CDN의 `ch-plugin-core-20260917193237.js`를 로드했다.
- 샘플 앱의 버튼과 JSON 입력 창을 Playwright로 조작했다. SDK를 mock으로 교체하지 않았다.
- 관찰용 JS Proxy가 SDK 호출과 콜백을 그대로 전달하면서 완료 시점·성공 여부를 기록했다.
  원본 사용자 객체와 키는 결과 보고서에 남기지 않았다.
- 샘플의 결과 표시, 실제 메신저 화면, SDK 콜백과 HTTP 응답을 구분해 확인했다.

## 실패 경로에서 발견한 제한

모든 값이 0인 가상 UUID를 plugin key로 넣어 `boot`를 호출했다.
SDK의 플러그인 정보 요청은 HTTP 422를 받았지만, 관찰 종료 시점인 약 147초까지
SDK 부팅 콜백이 호출되지 않았다. 현재 Web 구현은 콜백을 기다리므로 해당 Future와
샘플의 결과 표시도 완료되지 않았다. 이 관찰만으로 무기한 대기를 단정하지 않는다.

정상 키 재부팅은 성공했다. 이번 실패 경로는 SDK 오류 콜백이 들어왔을 때의
`false`/`unknown` 매핑을 실제로 검증한 것으로 세지 않는다.
기존 응답 처리와 완료 시점을 보존하라는 요구에 따라 타임아웃·반환형 변경은 하지 않았다.

## 미검증과 남은 조건

- 프로필·`customAttributes`·`profileOnce`·태그의 실제 서버 수정: 승인 대기.
  자동 승인 검토가 프로필 전송과 수신 설정 변경이 포함된 초기 부팅을 거부했다.
  이후 해당 필드를 모두 제외한 익명 부팅으로 진행했다. 수신 설정은 변경하지 않았다.
- 팝업 데이터와 timestamp: 실제 메시지·마케팅 팝업 이벤트를 발생시키지 않아 미검증.
  SDK의 기본 인사 팝업이 표시된 것만으로 timestamp 검증을 통과 처리하지 않았다.
- 상담 생성·메시지 전송·워크플로 실행·추적 이벤트 전송은 수행하지 않았다.
- Android/iOS 전용 API와 앞서 기록한 미구현 확장 API는 이번 Web 검증 범위 밖이다.
- SDK 부팅으로 생성될 수 있는 익명 방문 기록은 삭제하지 않았다.
  `shutdown`은 서버 사용자 레코드 삭제를 의미하지 않는다.

이번 검증에서는 런타임 소스를 바꾸지 않았고 기존 137개 플러그인·31개 샘플 자동 테스트를
다시 실행하지 않았다. 기존 mock 기반 결과와 이번 실제 SDK 결과를 구분한다.
